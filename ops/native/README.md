# 백엔드 배포

공개 저장소의 GitHub Actions 표준 Ubuntu x64 runner에서 네이티브 이미지를 빌드합니다. 정기 배포에 Cloud Build와 유료 worker pool을 사용하지 않습니다.

`main`에 반영하거나 GitHub의 **Backend native release**를 수동 실행하면 다음 절차를 수행합니다.

1. 현재 운영 리비전과 실행 설정을 기록합니다.
2. 단위 테스트, Testcontainers Firestore와 MySQL 통합 검사, 커버리지, AOT 생성을 확인합니다. 통합 검사가 건너뛰어지면 실패합니다.
3. `Dockerfile.native`로 Linux amd64 이미지를 한 번 빌드합니다.
4. 같은 이미지를 로컬 Firestore 에뮬레이터에 연결해 일정, 장소, 세션, ICS와 22개 언어를 검사합니다.
5. 짧은 수명의 GitHub OIDC 인증을 새로 받아 이미지를 Artifact Registry에 올립니다.
6. 이미지 digest로 트래픽 없는 후보를 배포하고 검증합니다.
7. 같은 후보에 운영 트래픽을 10%, 50%, 100%로 전달합니다. 실제 도메인의 22개 언어 API도 확인합니다.

빌드 중 다른 작업이 운영 트래픽이나 실행 설정을 바꾸면 배포를 중단합니다. 검증 실패 시 이번 배포가 변경한 트래픽만 원래 리비전으로 되돌립니다. API 최소 인스턴스 1대, CPU 1개, 메모리 512MiB, 기존 인증과 서비스 계정은 유지합니다. 검증은 로컬 에뮬레이터에만 데이터를 쓰고 운영에서는 읽기 전용으로 수행합니다.

인증은 저장소 ID `1096873122`, 소유자 ID `43169705`, `main`, `.github/workflows/backend-release.yml`에 한정합니다. 저장소의 비밀 키를 만들거나 저장하지 않습니다. 전용 배포 계정은 기존 이미지 저장소에 쓰기, 기존 API 서비스 배포, 해당 런타임 계정 사용 권한만 가집니다.

배포 상태, 테스트와 커버리지 결과, 네이티브 실행 로그는 각 Actions 실행의 artifact로 7일 보관합니다. 실행 파일 빌드에는 약 16GiB RAM과 최대 10GiB의 빌드 힙을 사용합니다. macOS ARM에서 x64 네이티브 빌드를 대신 수행하지 않습니다.

현재 운영 소스는 `docs/production-source-baseline.json`에 기록한 이미지와 Cloud Build 원본 아카이브의 SHA256으로 대조했습니다. 이 파일은 이전 당시의 기준이며 이후 기능 수정은 정상적인 코드 검토와 테스트를 거칩니다.

태그 도구는 프런트엔드의 `scripts/cloud_run_guard.py`와 같은 구현을 백엔드에도 보관합니다. 태그 생성과 배포 명령 모두 이 도구를 사용합니다.

GitHub 표준 runner의 빌드 실행 요금은 공개 저장소에서 무료입니다. 이미지 저장, 로그, 네트워크와 Cloud Run 운영 요금은 별도로 발생할 수 있습니다. 기존에 발생한 Cloud Build 청구액이 취소되는 것은 아닙니다.
